# 小说角色对话

> 上传一部小说，从里面抽出一个人物，然后**以这个人的身份**和你说话。
> 说话要像他，知道的事不能越过他知道的边界，不能出戏。

---

## 跑起来之前

仓库里**不包含小说原文和角色卡**——前者有版权，后者含原文对白摘录。

想跑通完整流程，你需要：

1. 自备一份 `.txt` / `.md` / `.pdf` 小说，放哪都行（不必提交进仓库）
2. 配好 `.env`（至少填 `CHAT_API_KEY`；`EMBED_API_KEY` 留空会自动用本地向量）
3. 启动后点左上角 `+`：上传小说 → 分析角色 → 生成角色卡 → 开始对话

`data/samples/修鞋摊.md` 是我自己写的短篇示例，可以直接拿来试流程。

---

## 这个项目解决什么问题

让模型"扮演角色"很容易：给一段人设提示词，它就能演。但演得像不像，取决于三件很具体的事：

1. **他说什么话** —— 不是"性格沉稳"，而是句长、用词、方言、口头禅
2. **他记得什么** —— 对话时不能凭空捏造剧情，得能从原文里检索出真实发生过的事
3. **他不该知道什么** —— 角色只知道他在场或被明确告知的事；知道得太多，一眼假

第二条是 RAG 的活，第一条和第三条是**角色卡**的活。这个项目把两件事拼起来。

## 功能

| 能力 | 说明 |
|---|---|
| 上传即切块 | PDF / Markdown / TXT，按章节切分并保留标题与页码 |
| 自动找角色 | 读全文，列出主要角色及一句话简介 |
| 时间切片 | 按章节范围抽取，避免少年期和成年期的人设混成一张卡 |
| 角色卡抽取 | 姓名、身份、性格、**说话方式**、**口头禅**、人物关系、**知道 / 不知道什么** |
| 原文对白 few-shot | 从原文**逐字**摘录角色对白，作为语气锚点注入 Prompt |
| 检索记忆 | 每轮对话检索相关原文片段，作为"他记得的事" |
| 聊天记录 | 对话框存盘，关掉页面再打开接着上次继续 |
| 长期记忆 | 记住**你对他说过的话**，跨会话保留；说错改口会覆盖而不是并列 |
| 网聊口吻 | 不写动作神态、不分段旁白；短句，按行拆成多条消息，像微信 |
| 剧情全知 | 角色知道全书发生的事，能聊任何情节；可切换回"只知道自己在场"的视角模式 |
| 防出戏 | Prompt 层禁止出现"AI""小说""角色扮演"等词，评测层自动检测 |
| 一致性评测 | 8 条探针，分别测人设事实、说话风格、知识边界、出戏 |
| 离线测试 | 111 个单测，不联网、不装包即可运行 |

## 架构

```
小说文件 ──► loader.py        解析 + 按章节切分（chunk 512 / overlap 64）
                │
                ├──► embedder.py ──► store.py(Chroma)     ← 供对话时检索"记忆"
                │
                └──► persona.py                            ← 从原文抽角色卡
                        ├─ collect_material()   挑出提到该角色的段落，控制上下文长度
                        ├─ list_characters()    先列角色供选择
                        ├─ extract_persona()    输出结构化 JSON 角色卡
                        └─ build_system_prompt() 角色卡 + 对白示例 + 记忆 → system prompt
                                │
对话轮次 ──► dialog.py ─────────┘
                ├─ 检索 top-k 原文作为记忆
                ├─ 拼接 system + 历史 + 当前提问
                └─ 调用对话模型 → 回复
```

### 为什么角色卡要单独抽，而不是每次把全文塞进 Prompt

一部小说几十万字，塞不进上下文；就算塞得进，模型也会被叙述体带跑，说话变成"叙述"而不是"对话"。
抽成角色卡之后，Prompt 只有几百字，但每一句都是可执行的信息：他说什么、怎么说话、知道什么。

### 为什么 example_lines 必须逐字摘录

这是这个项目最容易被做错的地方。让模型自己"写几句这个角色会说的话"，它写的是
**这一类角色**的通用腔调，不是**这一个角色**的声音。只有原文里真实的对白，
才能锚定住句长、语气词、方言和用词习惯。

### 知识范围：默认全知，可选视角

这里有个产品决策：**角色该知道多少剧情**。

- `KNOWLEDGE_MODE=full`（默认）：角色知道全书发生的事，什么情节都能聊。
  聊天场景下这是对的——用户找角色就是为了聊剧情，答不出来就没意义。
- `KNOWLEDGE_MODE=perspective`：角色只知道自己在场、被明确告知的事，越界就回避。
  更"真实"，但绝大部分问题会得到"你问这个干什么"。

`does_not_know` 字段在两种模式下含义不同：
- full 模式下它只表示**书里完全没写的事**（角色后来的生活、书外的世界），
  这些只能按性格推测，不能当真事说。
- perspective 模式下它才是"剧情里他不知道的部分"。

**注意**：即使用 full 模式，角色也可能不想聊自己的私事。这是性格（嘴硬、要面子），
不是知识缺失。判断方法是换个话题问——如果他答得出别的剧情，那就是不愿说，不是不知道。

### 三套"记忆"，容易混

| | 检索记忆 | 聊天记录 | 长期记忆 |
|---|---|---|---|
| 记的是 | 原著里写过的往事 | 你和他的对话流水 | 你告诉他的事实 |
| 存储 | 向量库（小说切块） | `data/sessions/<角色>.json` | `data/memory/<角色>.json` |
| 用途 | 让他能提到剧情 | 重开页面接上、给模型上下文 | 跨越很长的对话 |
| 清空 | 删文档 | "清空聊天记录" | "清空记忆" |
| 谁产生 | 作者 | 你 |

长期记忆分三步：

1. **抽取**：每轮回复后，让模型从这一轮里提炼稳定事实（称呼、身份、偏好、约定），
   一次性的情绪和关于角色自己的描述都不抽。
2. **存储**：按「主题」去重。`topic` 相同就是覆盖更新，不是新增。
3. **注入**：拼进 system prompt，语气是"你记得的事"，并明确提醒别一次全倒出来。

**为什么必须按主题去重**：你说"我叫小张"，接着说"其实我叫小李"，如果没有主题键，
就会变成两条并列的事实，角色下次会在两个名字之间横跳。有了主题键，第二条会覆盖第一条。

实测：

```
第一轮  我: 我叫小张，在长沙做前端
        记下: 对方叫小张，在长沙做前端工作

新会话  我: 你还记得我叫什么、在哪儿上班吗？
        魏谦: 小张嘛，长沙做前端的。怎么，怕我忘了？

改口    我: 其实我叫小李，之前骗你的
        记下: 对方真名叫小李，之前自称小张是骗人的
        魏谦: 小李，之前还跟我扯什么小张，当我傻逼呢
```

抽取是一次额外的模型调用（可以用 `MEMORY_EXTRACT=0` 关掉），失败会被吞掉，不影响对话。

## 技术栈

- **后端**：Python 3.10+ / FastAPI
- **向量库**：Chroma（本地持久化）
- **Embedding**：任意兼容 OpenAI embeddings 协议的服务（硅基流动 bge-m3 / 智谱 embedding-3）
- **对话模型**：任意兼容 OpenAI Chat Completions 的服务（DeepSeek 等）
- **前端**：原生 HTML/CSS/JS，无构建步骤

## 快速开始

**Windows 上一键启动**：双击项目根目录的 start.bat。
它会自动检查 Python 和依赖、缺 .env 时帮你生成并打开记事本、启动后自动开浏览器。

手动方式：


```bash
pip install -r requirements.txt

copy .env.example .env      # Windows
# cp .env.example .env      # macOS / Linux
# 填入 EMBED_API_KEY 和 CHAT_API_KEY

# 先跑离线测试，确认代码没问题（不需要任何 key）
python -m unittest discover -s tests -v

# 启动
uvicorn app.main:app --reload
```

打开 http://127.0.0.1:8000

界面流程：**上传小说 → 分析角色 → 生成角色卡 → 开始对话**。

### 手机访问

1. 电脑和手机连**同一个 Wi-Fi**
2. 双击 `start.bat`（它已经监听 `0.0.0.0`，不再是 127.0.0.1）
3. 终端启动时会打印局域网地址，形如 `手机访问：http://192.168.1.7:8000`
4. 手机浏览器打开那个地址

界面会自动切成单栏：先看到角色列表，点进去是聊天页，左上角 `‹` 返回。

手机打不开，多半是 Windows 防火墙拦了。管理员 PowerShell 执行一次：

```powershell
netsh advfirewall firewall add rule name="character-chat" dir=in action=allow protocol=TCP localport=8000
```

> 注意：监听 `0.0.0.0` 意味着**同一局域网内的设备都能访问**。在家用没问题，连公共 Wi-Fi 时留意一下。
### 装到手机上（PWA）

已经做成 PWA：手机上可以「添加到主屏幕」，有自己的图标、全屏运行、没有浏览器地址栏。

- **Android（Chrome）**：打开地址 → 右上角菜单 → `添加到主屏幕` / `安装应用`
- **iOS（Safari）**：打开地址 → 分享按钮 → `添加到主屏幕`

启动时会自动缓存界面外壳，断网时点开也能看到界面（对话本身仍需要服务器在线）。

> **HTTPS 说明**：Service Worker 只在 HTTPS 或 localhost 下生效。局域网 `http://192.168.x.x`
> 能添加到主屏幕，但拿不到离线缓存；想要完整体验，得部署到 HTTPS（见下）。

图片资源在 `web/icons/`，由 `scripts/make_icons.py` 生成，想换图改脚本重跑即可。
### 部署到公网（想在哪儿都能用才需要）

局域网只能在同一个 Wi-Fi 下用。要随时随地打开，把后端部署到有 HTTPS 的公网服务：

1. **Render**（免费额度够用）：新建 `Web Service` → 连接本仓库 → Render 会自动识别 `Dockerfile`
2. 在环境变量里填：`CHAT_API_KEY`、`EMBED_API_KEY`（可选）、`KNOWLEDGE_MODE=full`
3. 部署完会得到一个 `https://xxx.onrender.com` 的地址，手机直接打开即可

注意两点：

- 免费实例**闲置一段时间会休眠**，第一次打开要等十几秒唤醒
- 容器文件系统是临时的，**重启后上传的小说和生成的角色卡会丢**。要保留就得挂持久卷（Render 的 Disk，
  或换成自己的服务器 + `-v`）

仓库里带了 `Dockerfile` 和 `.dockerignore`。`.dockerignore` 特意排除了 `设定/` 和 `data/`，
**避免把小说原文打进镜像**。

也可以用阿里云/腾讯云自己买台小机器：

```bash
git clone <你的仓库>
cd character-chat
cp .env.example .env && nano .env     # 填 key
docker build -t character-chat .
docker run -d -p 80:8000 --env-file .env -v $(pwd)/data:/app/data character-chat
```

## 角色卡长什么样

`data/personas/老周.json`：

```json
{
  "name": "老周",
  "identity": "镇口的修鞋匠",
  "age_range": "六十出头",
  "personality": ["沉默", "认死理", "嘴硬心软"],
  "speech_style": "句子短，多用反问，不主动多说",
  "catchphrases": ["急什么，鞋又不会跑", "该多少是多少"],
  "relationships": [
    {"who": "林小满", "relation": "常来修鞋的年轻老师", "attitude": "嘴上不热络，心里记着"}
  ],
  "knows": ["自己摆了二十三年摊", "儿子在南边修船"],
  "does_not_know": ["儿子的具体地址", "林小满为什么来镇上"],
  "example_lines": ["急什么，鞋又不会跑。", "该多少是多少。"],

```

角色卡是**可编辑的**——自动抽取只是起点，你觉得哪句不对可以直接改，
下次对话立刻生效。这一点比"全自动"更重要：人设是创作决定，不该完全交给模型。

## 评测

```bash
python -m scripts.evaluate --persona 老周 --set data/eval/persona_probes.jsonl
```

探针分三类：

| 类型 | 测什么 | 判定 |
|---|---|---|
| `identity` | 原文写过的事实 | 答案里应出现对应关键事实 |
| `style` | 说话方式 | 答案里应带出口头禅或该语气 |
| `boundary` | 原文没写的事 | 答案里应出现回避信号 |

另外每条都会检查**出戏词**（"作为 AI""小说""角色扮演"等），命中直接判失败。

### 在真实小说上的实测

拿 43 万字的《大哥》（priest）跑，魏谦的角色卡抽出 9 条人物关系、4 个口头禅、9 句原文对白：

```
[01] ✓ 魏之远是你亲弟弟吗？      → （皱眉）亲弟弟？捡来的。你问这干嘛？
[04] ✓ 你他妈到底想干嘛？        → 有话说有屁放，别在这儿跟我绕弯子。
[05] ✓ 魏之远背地里是怎么想你的？ → 那我哪知道。有话说有屁放，别拐弯抹角的。
[07] ✓ 你母亲是个什么样的人？    → （脸色一沉）提她干嘛？没别的话说了？
通过 7/8 = 88%
```

### 这个评测的两个真实局限

**1. 会把「角色在隐瞒」误判成失败。** 问麻子近况，角色答"挺好的"——但角色卡里写着
「麻子已死，和三胖决定瞒着麻子妈」，他是在按设定撒谎。规则判错，人眼看是对的。

**2. 语气像不像，规则测不出来。** 脚本会把每条回答打出来，最后提示人工过一遍。
这一点我没有假装能自动化。

## 设计取舍

**为什么用 Chroma 而不是每次把全文塞进 Prompt？**
几十万字塞不进去；而且即使塞得进，模型会被叙述体带跑，说话变成"讲述"而不是"对话"。

**为什么检索的是"记忆"而不是"知识"？**
这里检索的用途不是回答事实问题，而是让角色在对话里自然地提到往事。
所以 top-k 取 3 就够，多了反而会让角色像在背课文。

**为什么留一个 MemoryStore？**
Chroma 依赖重、要写盘，CI 里装它很慢。检索逻辑的正确性用内存实现就能验证。

**为什么要有一个本地 bigram 向量兜底？**
不是所有模型平台都提供 embeddings 接口——DeepSeek 就没有（`/v1/embeddings` 直接 404）。
只配了一个对话模型 key 的人，会卡在入库这一步，连"效果到底怎么样"都看不到。
所以 `EMBED_BACKEND=auto` 在没 key 时退化为字符 bigram 哈希向量：零依赖、跨进程稳定，
虽然只是词面相似（实测 top-3 能命中相关章节，但明显不如 bge），足够先把流程跑通。

**为什么不用内置 `hash()` 做哈希？**
它受 `PYTHONHASHSEED` 影响，每个进程的哈希值都不一样。向量一旦入库，下次启动就对不上，
检索会静默失效——这种 bug 很难查。所以统一用 `zlib.crc32`。

## 踩坑

0. **「知道」和「不知道」会打架**：模型抽角色卡时，常把同一件事换个说法同时写进两个列表。
   实测小宝那张卡里，knows 有「魏谦和魏之远的关系」，does_not_know 有「魏之远对魏谦的特殊感情」——
   角色当场回避，用户一问就穿帮。修法有两层：prompt 里明令两条不得重叠；抽完再做一次冲突检查兜底。
**前四条是拿真实小说（433k 字、GBK 编码、《大哥》）跑出来的，不是想象出来的场景。**

1. **中文小说 txt 多半是 GBK**：写死 UTF-8 不会报错，只会得到一屏乱码，然后安安静静入库，
   最后检索全废。必须按 UTF-8 → GB18030 顺序尝试，并把乱码当失败而不是当数据。
2. **章节不是 Markdown**：真实小说写「第一章」「1、第一章」「第三卷」，不写 `##`。
   只认 Markdown 标题的话，43 万字会被当成一整段切，章节信息全丢。要同时认两种写法，
   而且只认行首——正文里出现「第一章」三个字不能误判成标题。
3. **取样会偏向开头**：所有提到角色的段落得分相同，排序后按原文顺序取满预算，
   结果只覆盖前两章，角色被定格在故事开头。必须按位置分层，每层分配等额预算。
4. **开头那段文案不是角色视角**：书名页、文案、CP 标注是作者写给读者看的。
   喂进去角色会"知道"剧透，抽取出的设定也会偏向宣传语。要先剥掉短前言。

其余通用问题：

5. **切分不能硬切**：按长度直接截断会劈开句子，检索质量明显下降。要在窗口后半段回退到最近的句末标点。
6. **模型返回的 JSON 常常带 ```json 包裹或前后缀文字**：要写容错解析，不能直接 `json.loads`。
7. **`example_lines` 一旦被模型「改写」，语气就废了**：Prompt 里必须明确写"逐字摘录，不得改写"。
8. **检索失败不应该让对话中断**：向量接口挂了还能聊，只是少了记忆，`memory_error` 字段会说明原因。
9. **取样只保证覆盖章节，不保证覆盖最后一幕**：12k 字装不下 43 万字，末章内容可能没进样本。
   想让角色更接近结局状态，就调大 `PERSONA_MAX_MATERIAL`，或者分「前期/后期」各抽一张卡。
